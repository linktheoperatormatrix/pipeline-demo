# Связка Jira + GitHub

Как задача из Jira доезжает до мержа и возвращается закрытой. Канбан-доска:
<https://linktheoperatormatrix.atlassian.net> (проект `KAN`).

## Цикл

1. **Задача.** В проекте `KAN` создаётся задача, например `KAN-1`.
   Типы: Задача, История, Баг, Эпик, Feature. Статусы:
   «К выполнению» → «В работе» → «In Review» → «Готово».
2. **Ветка.** От свежего `main` — ветка `KAN-<номер>-<краткое-имя>`,
   например `KAN-1-jira-github-flow`. Прямые пуши в `main` — нет.
3. **Коммиты.** Ключ задачи в первой строке: `KAN-1: добавить X` —
   история `git log` читается как отчёт по доске.
4. **PR.** `gh pr create`, заголовок `KAN-<номер>: <суть>`. Дальше
   работает конвейер из README: локальные хуки на push, в PR — линт,
   тесты, gosec, gitleaks и ревью-агент.
5. **Обратная ссылка.** PR привязывается к задаче через remote link
   (Jira API) — на карточке появляется кликабельный PR.
6. **Финиш.** Мерж (`--squash`), удаление ветки, локальный `main`
   подтягивается, задача переводится в «Готово» с итоговым комментарием.

## Почему ключ задачи везде

Единый ключ `KAN-<номер>` в ветке, коммитах, PR и Jira сшивает системы:
по нему из любого места находится весь контекст — код, обсуждение и
статус. Без него связка рассыпается на «какой-то PR» и «какая-то задача».
